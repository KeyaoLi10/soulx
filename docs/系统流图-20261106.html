§0一句话与分层总览

一个 0.6B 流式语义轮次预测模型（SoulX-Duplug）挂在 Qwen3.5-9B 快慢脑双实例 + VoxCPM2 流式 TTS 级联前端上， 外加 pre-ASR 主说话人迟滞门控（pvad 流门控 + 影子声源分离）、五层话轮边界防御、快慢脑双循环 Agent（legacy）， 以及本轮新实施的 Agent Runtime V2 控制平面（SQLite 持久化任务协议 · 快脑语义路由 · 三态交付），构成全双工中文语音对话系统。

§1全局架构图（数据流 + 控制流）

下图是整个系统的一次完整环流：上行（琥珀色）从麦克风经 WebRTC 处理、WS 二进制帧进入 web app 接收循环， 旁路喂 pvad 打分 / tse 影子分离，过流门控后进 turn server 状态机；轮次提交（绿色）携带整句转写回到话轮管线； 生成（蓝色）在快脑流式分段，经统一语音出口送 TTS 合成、下行回浏览器； V2 控制面（紫色）是本轮改造新增的旁路——默认不创建，仅 AGENT_RUNTIME_MODE 显式开启时存在。

1.1 一次对话的端到端时序（文字版）

  1. 上行：麦克风 → 浏览器 WebRTC 链 → WS 二进制帧（16 kHz float32，160 ms）→ web app 接收循环（异采样率 soxr VHQ 重采样）。
  2. 旁路与门控：原始 chunk 先进 pvad ring（1.2 s 尾窗）与 sidecar feed（打分器必须看到真实麦克风，否则门永远无法解除）， 再过 stream_gate_filter——enforce + 已注册 + 主动压制时把 chunk 替换为全零块；tse :8087 仅影子观测 sep_cos。
  3. 轮次判别：chunk 进 turn server 状态机（0.6B 逐 chunk），五道门滤掉毛刺；wait（连续静音 max_wait_num 块）或 complete（<|user_complete|> 即触发）提交话轮，携带整句转写 + trigger + commit_id。
  4. 两遍式 ASR：turn server commit 后立刻整句重识别并异步推 turn_final；话轮管线在后台线程 hold ≤500 ms 等它，拿到更准的整句文本再继续（超时回落 live 文本）。
  5. 管线：自说自话过滤 → 主说话人门 → 提交上一轮 pending → interrupt/reset → 历史 → 生成分支（详见 §4）。
  6. 生成与播放：快脑流式分段 → 统一语音出口：宽限保持（complete 触发时）→ text_response → TTS 流式 → audio_chunk 下行 + 双轨录音；播完挂 pending_message，下一轮话轮提交时才写进历史。
  7. 打断：播放期用户复语 → pvad barge-in（间隙容忍累积证据）→ cut_pending_audio + interrupt → 三态返回。

§2上行链路：麦克风 → 轮次提交

上行链路的设计原则：门控在 ASR 之前（非主说话人音频根本不进转写与轮次判别），打分在门控之旁 （打分器必须持续看到原始麦克风，否则压制永远无法解除），修正在线程之内（两遍式 ASR 的 hold 发生在话轮 后台线程，绝不阻塞事件循环）。

2.1 pvad 流门控：迟滞状态机

两个说话人的 ECAPA 余弦分数带完全重叠（用户 −0.06–0.39 vs 背景 0.11–0.40），任何单一阈值都不可行， 因此用迟滞 + 死区：进入压制要求连续 2 轮显著低于阈值，解除只要求一轮回到阈值之上。

§3话轮边界五层防御级联

一次"用户复语 / 背景噪声 / 回声"事件要成为一次合法话轮，必须依次漏过五层防御。 每层只杀一类目标，层与层不合并阈值（mm=3 与 D=5 不可合并是实测结论）。

§4话轮管线与统一语音出口（生成 → 播放）

话轮管线是"说完之后怎么办"的唯一实现——两条轮次引擎（soulx / frc）在这里汇合。 它先过一遍收尾防御（自说自话 / 主说话人门），再决定谁来生成（V2 enforce 接管 / legacy 快脑）， 最后所有输出汇入统一语音出口：用户话轮回复与后台任务交付共用同一条 _run_speech_pipeline， 一个 turn_start、一个 pending-message 生命周期、一套三态返回。

4.1 双轨录音与打断取证

TTS 发射快于实时（RTF ≈0.36），浏览器在打断瞬间丢弃缓冲，但旁路可能已持有"已发射未播放"的尾巴。 _SessionAudio 以播放时钟（首发射时间）为 run 锚点：每次管线启动 run_break(first_emit_time) 声明断流（迟到的 mark_cut 永远切不到新管线的 run）；打断路径 cut_pending_audio → mark_cut(t, since) 把录音切在可听播放真正结束处。pvad barge-in、话轮提交、交付入口、duplex_stop、连接关闭六个入口都先切刀再 interrupt。

§5快慢脑 Agent（legacy 路径）

legacy 快慢脑是"确定性逻辑放 Runtime、概率性逻辑放模型"的现行实现：快脑只做即时交互与意图表达， 慢脑在后台跑工具循环；两者之间的所有承诺（取消 / 委派 / 交付时机）由 AgentRuntime 用代码仲裁， 不依赖模型自觉。V2（§6）把同一思想升级为显式协议 + 持久化。

§6Agent Runtime V2（手册实施，默认关闭）

V2 是 2026-11-06 按手册落地的显式协议化 agent 运行时：路由（快脑出 Plan）、持久化（SQLite 唯一事实源）、 调度与交付分离（run 围栏 + outbox 至少一次）。它与 legacy 的关系由单一环境变量 AGENT_RUNTIME_MODE=legacy|shadow|enforce（app.py:89，非法值 → legacy）决定， 默认 legacy：V2 全部为死代码，语音路径与改造前字节等价。语音前端是第一公民——V2 只读注入： grace 阈值取同一份 turn_grace_ms、话权判断取现有 _agent_can_deliver、 发声复用同一条 _run_speech_pipeline，不复制任何语音逻辑。

§9设计不变量（改代码前必读）

  1. 未说出口的话绝不进历史——截断残段、held 未播文本、premature 丢弃的整次生成都会污染下一轮生成。
  2. 跨线程 / 跨服务的异步结果必须带代际校验——宽限窗（stop_event 代际）、双 EOT（decision_gen）、双轨取证（run_break 播放时钟锚定）均为实例。
  3. 确定性逻辑放 Runtime，概率性逻辑放模型——auto_cancel / 交付仲裁 / 提及注入 / V2 的 G2 解析层拦截，都是从提示词下沉到代码的同一思想。
  4. pvad 与 tse 一律旁路、fail-open——feed 是队列 put 不进轮次路径；信号未知时放行，宁可多说不宁可不响。
  5. 两条引擎共享同一条 pipeline_worker 与语音出口——前端模式只换"什么时候算说完"，不换"说完之后怎么办"。
  6. 语音前端是第一公民（2026-11-06 起）——V2 只读注入：grace 阈值同一份、话权判断同一个、发声同一条管线；shadow 绝不抢 GEN_LOCK；enforce 下旧 runtime 不启动防双出口。
  7. 空结果绝不谎报成功——V2 慢脑空流 → failed(outcome=empty)；空流判别量精确到"掐死在首分句前"。
