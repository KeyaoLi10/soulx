## 1. 项目定位

在 [SoulX-Duplug](https://github.com/Soul-AILab/SoulX-Duplug)（0.6B 流式语义 VAD / 轮次状态预测模型）的开源级联底座上，构建了一套**可现场演示的全双工中文语音对话 Agent 系统**：

- **听得懂轮次**：用户说完才接话、句中停顿不抢话、随时可打断；
- **有大脑**：快脑（即时交互）+ 慢脑（后台异步任务）+ 确定性 Runtime 仲裁的双循环架构；
- **能干活**：联网搜索、网页抓取、Python 计算、定时任务，结果在对话空档期自然播报；
- **双前端可切换**：SoulX 轮次引擎与 FireRedChat 双 EOT 架构一键热切换，TTS/LLM 完全共用。

替代原件（本机资源约束）：Qwen2.5-7B → **Qwen3.5-9B**，IndexTTS/CosyVoice → **VoxCPM2（自训 LoRA + 参考音色锚定）**。

## 3. 系统架构

```
用户音频 16kHz/160ms chunk
   │
   ├──[soulx 引擎·默认] turn server :8000（GPU5）
   │     SoulX-Duplug-0.6B 状态机 idle/nonidle/speak
   │     + paraformer 转写；trigger: complete(立即)/wait(静音确认)
   │
   └──[frc 引擎·可切换] Settings 热切换，代码零侵入
         pvad :8086 通用 VAD（0.4s 静音=EOS，2.5s 前滚防切头）
         → 双通道 EOT 并行：ultraVAD :8082（音频+助手文本）
                        × :6007 /v1/score（ASR 转写语义判别，~60ms）
         → min 融合 ≥0.2 快速提交，否则 hold 至 EOS+6s；复语取消
         → FireRedASR :8010 整句转写（PUNC+ITN）
   │
   ▼
Web app :8090 ─ pipeline_worker（门控→历史→生成→TTS→推送）
   ├─ complete 触发 → 0.9s 宽限保持窗（抢话修复）
   ├─ 快脑 :6007 thinking=off，/agent_chat 原生 tool calling
   │    （delegate_task / cancel_task）
   ├─ AgentRuntime：任务表 / 议程 / 空档期交付仲裁 / auto_cancel
   └─ 慢脑 :6008 后台 agent 循环：web_search(DDG→百度回落) /
        fetch_page / python_repl(沙箱) / get_datetime
   │
   ▼
每段回复 → VoxCPM2 TTS :8085（LoRA r=32 + 锚定音色）→ 24kHz PCM
```

**服务矩阵**（tmux 会话 `soulx`，10 窗口）：turn:8000 / ultravad:8082 / frcasr:8010（GPU5）；llm:6007（GPU6）；slowllm:6008（GPU1）；fireredtts:8081 / voxtts:8085（GPU7）；pvad:8086（CPU）；web:8090。

## 4. 核心技术点

### 4.1 抢话修复：complete 触发宽限窗（10-30）

- **根因**：`<|user_complete|>` 预测一出现立即接话，零静音确认；中文句中停顿被 0.6B 模型误判为说完。
- **方案**：speak 返回标注 `trigger`；complete 触发话轮获得 0.9s 保持窗——LLM 照常流式生成但对用户不可见；窗口内持续复语即**静默丢弃整次生成**（未说出的回复不进历史），用户续说经 groupby 并成完整 utterance。wait 触发（已有 5 块静音确认）不受影响。
- **连带修复**：E2E 委派失败根因正是话轮碎片化——TTS 句间停顿把一句话切成 4 个 complete 话轮，截断残段污染历史让模型误以为已委派。修复后 E2E 8/11 → **11/11**。
- **实现教训**：held 分段必须独立列表、窗口过期逐段正常 emit；首版直接累进 `message_to_add`，短回复在窗口内生成完时**从未播放却进了历史**（config_ws_test 抓到）。

### 4.2 FRC 前端模式：双 EOT 架构移植（10-30）

- ultraVAD（音频通道）+ Qwen3.5 首 token 概率打分（语义通道，`/v1/score`，一次 prefill ~60ms）并行判 EOT，**min 融合**双确认才快速提交；实测整句 uv=0.908/llm=0.940，半句 0.088/0.018 稳定 hold。
- 决策代际计数防"复语 → 新 EOS → 旧 HTTP 结果晚到"竞态；pvad 概率滞后 ~1-2 块实际静音判据 ≈0.6-0.7s，恰好更保守。
- 与 soulx 模式取舍：无实时转写（整句后置）、依赖 3 个额外服务，但语义 EOT 对句中停顿的判别远强于轮次模型。

### 4.3 快慢脑 Agent 双循环（10-29）

- 快脑即时交互 + 慢脑异步任务 + **确定性 Runtime 仲裁**（任务表/议程/交付时机=用户空闲+无播放+无生成的空档期）。
- 关键设计：**改口取消由 Runtime 确定性执行**（`auto_cancel` 正则先行取消再注入确认提示——快脑实测会说"已取消"却不调工具）；**任务状态按提及注入**（`_TASK_MENTION_RE`，慢脑运行期间闲聊不汇报，提及才同步进度）；工具轮次不进持久历史；结果以 user 角色系统提示注入。
- 提速：慢脑 thinking 默认 off（思考轮重尾 5-100s+ 是慢的主因），DDG 搜索经 curl 直连（requests TLS 指纹被反爬挑战）+ 百度回落。天气类任务 15-25s → 6-9s。

### 4.4 语音质量：VoxCPM2 跨段音色一致（10-29）

- zero-shot 模式每段从新高斯采样，段间 ECAPA 余弦最低 0.22（一段一个随机音色）→ **参考克隆锚定**（启动时锚定 `data/voxcpm_anchor.wav`，prompt cache 一次全段复用）+ **自训 LoRA**（r=32，step_0000500）→ 0.65-0.75。首块 80ms，RTF 0.32。

### 4.5 主说话人门控（PVAD）探索与收敛（10-29~30）

- 完整实现了 ONNX 个性化 VAD + ECAPA 门控 sidecar（三态 off/shadow/enforce、话轮音频 bank 滚动注册、音频取证落盘），并修掉了打断风暴、注册库污染死亡螺旋等一系列问题。
- **最终结论：默认下线**。浏览器 WebRTC 链路（AEC/降噪）下同人 ECAPA 余弦仅 0.15–0.57，低于干净音频标定的 0.5 阈值，enforce 持续误拒注册用户本人——这是"30 秒后不说话"系列故障的终极根因。代码全保留，Settings 可切回。

## 6. 问题梳理与经验教训

**故障时间线**（详见 `docs/修改日志.md` 24 条）：
1. **基础设施期**（10-26~27）：FireRedTTS SYNTH_LOCK 跨 yield 死锁（"几轮后沉默"）；浏览器 WS 无重连；VoxCPM2 音色漂移。
2. **轮次/门控期**（10-29~30，问题最密集）：打断风暴、播放中沉默、播放期宽容证伪、毛刺过滤上线当天下线、注册库污染螺旋、PVAD 整体下线、抢话。
3. **Agent 期**（10-29~30）：双重受理、改口不取消、工具调用慢、held 不播出、心算跳工具。

**共性教训**：
1. **浏览器 WebRTC 链路系统性破坏声学判据**——干净音频标定的阈值（ECAPA 0.5、3 连续块）到线上全部失效；声学方案必须线上链路标定且 fail-open。
2. **异步结果必须带代际校验**——宽限窗、双 EOT 都被"旧请求晚到"击穿过；计数器优于 bool 标志。
3. **未说出口的话绝不能进历史**——截断残段与 held 未播文本都会污染下一轮生成（两个独立 bug 同根源）。
4. **确定性逻辑放 Runtime，概率性逻辑放模型**——auto_cancel、交付仲裁、提及门控做确定性远比指望模型"懂事"可靠；提示词规则服从率永远 <100%。
5. **每次"提速"都要跑行为回归**——thinking=off 提速 3 倍但偶发跳过 python_repl；思考模式 max_tokens 过低产出空答案。
6. **回归套件是自动化批次唯一的审稿人**——今晚两个 bug（held 不播出、心算跳工具）都是测试抓到的，不是人眼 review 出来的。
