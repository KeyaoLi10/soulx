SoulX-Duplug · Architecture Reference

系统架构总览

2026-10-30 · dev 2ffdc10 10 服务在线 · 4 GPU + CPU 双轮次引擎 · 快慢脑 Agent

0.6B 流式语义轮次预测模型挂在 Qwen3.5-9B + VoxCPM2 级联前端上：轮次层可在 SoulX 状态机与 FireRedChat 双 EOT 架构间会话级热切换，应用层以快慢脑双循环承载即时交互与后台任务，全链路共享同一条语音出口。

02

frc 引擎决策流

chunk → onset: 3 块连续 prob≥0.5（<3 块判噪声丢弃，携 2.5s 前滚防切头）
     → speech → EOS: 连续 0.4s prob<0.5（概率滞后 1-2 块，实际 ≈0.6-0.7s）· decision_gen 自增
     → 双通道并行（每步代际校验，防旧请求晚到）:
         ultraVAD :8082   20s 滚动音频窗 + 上一条助手文本
         /v1/score :6007  FireRedASR 转写 + 助手文本 → 是/否首 token softmax
     → min 融合（任一通道错误记 0）: 双确认 ≥0.2 → 快速提交
         否则 hold 至 EOS+6.0s 封顶；期间复语 → 取消待提交、话轮继续生长
     → 提交 → FireRedASR 整句转写（PUNC+ITN）→ 同一条 pipeline_worker（不叠加宽限）
# 实测：整句 uv=0.908 llm=0.940 提交；半句 uv=0.088 llm=0.018 hold+复语取消
# 边界：单话轮上限 60s；依赖 :8086/:8082/:8010 在线，宕机则该会话 frc 降级

设计不变量（改代码前必读）

01

未说出口的话绝不进历史——截断残段与宽限窗内未播文本都会污染下一轮生成（两个历史 bug 同根源）。

02

跨线程/跨服务异步结果必须带代际校验——宽限窗与双 EOT 都被"旧请求晚到"击穿过；单调计数器优于 bool 标志。

03

确定性逻辑放 Runtime，概率性逻辑放模型——auto_cancel、交付仲裁、提及注入都是从提示词下沉到代码的实例。

04

pvad 旁路不进轮次路径——feed 是队列 put；信号未知一律 fail-open，sidecar 宕机对话不受影响。

05

两条引擎共享同一条 pipeline_worker 与语音出口——前端模式只换"什么时候算说完"，不换"说完之后怎么办"。
