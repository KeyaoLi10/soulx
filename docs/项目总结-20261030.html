02

核心技术点

抢话修复 · 宽限保持窗

complete 触发零确认是抢话根源

「<user_complete>」一有预测立即接话；中文句中停顿被 0.6B 模型误判为说完。修复后 complete 话轮获得 0.9s 保持窗：LLM 照常流式生成但对用户不可见，窗口内持续复语即静默丢弃整次生成——未说出的回复不进历史，续说经 groupby 并成完整句。wait 触发（已静音确认）不设宽限。连带修复了 E2E 委派失败：其根因正是话轮碎片化截断残段污染历史，修复后 8/11 → 11/11。

FRC 前端 · 双 EOT 融合

语义判别力：整句 0.94，半句 0.018

ultraVAD（20s 音频窗 + 助手文本）与 Qwen 首 token 概率打分（/v1/score，一次 prefill ≈60ms）并行判 EOT，min 融合双确认才快速提交，否则 hold 至 EOS+6s 封顶，复语即取消。决策代际计数防「复语 → 新 EOS → 旧请求晚到」竞态。实测日志：

# 整句
uv=0.908 llm=0.940 → fast-commit
# 「帮我查一下明天早上」1.2s 停顿
uv=0.088 llm=0.018 → hold，复语取消
# 后半句接上后整句提交
uv=0.545 llm=0.932 → fast-commit
快慢脑 · 确定性仲裁

关键逻辑放 Runtime，不指望模型懂事

交付时机 = 用户空闲 + 无播放 + 无生成的空档期，经与用户话轮完全相同的语音出口。改口取消由 Runtime 确定性执行（快脑实测会说「已取消」却不调工具）；任务状态按提及注入——慢脑运行期间闲聊不汇报，用户问到才同步进度。工具轮次不进持久历史。

语音质量 · 音色一致

zero-shot 每段一个随机音色 → 锚定克隆

VoxCPM2 zero-shot 每次调用重新采样，段间 ECAPA 余弦最低 0.22；改为启动时锚定参考音色（prompt cache 一次全段复用）+ 自训 LoRA 后稳定在 0.65–0.75。首块 80ms、RTF 0.32，满足实时对话。

问题梳理与经验教训

五天累计 24 条故障修复记录（docs/修改日志.md，每条含根因 / 修改 / 验证 / 边界）。跨条目的共性教训：

01

浏览器 WebRTC 链路系统性破坏声学判据。干净音频标定的阈值（ECAPA 0.5、3 连续语音块）到线上全部失效——同人经 AEC 后余弦仅 0.15–0.57。声学方案必须在线上链路标定，且优先 fail-open；这正是 PVAD 门控最终默认下线的依据。

02

跨服务异步结果必须带代际校验。宽限窗与双 EOT 都被「旧请求晚到作用于新状态」击穿过；单调计数器比 bool 标志可靠。

03

未说出口的话绝不能进历史。截断残段与宽限窗内未播文本都会污染下一轮生成——两个独立 bug 同根源，前者直接导致委派失败。

04

确定性逻辑放 Runtime，概率性逻辑放模型。auto_cancel、交付仲裁、提及注入做成确定性的远比指望模型「懂事」可靠；提示词规则的服从率永远低于 100%。

05

每次提速都要跑行为回归。thinking=off 提速三倍但偶发跳过计算工具；思考模式 max_tokens 过低会产出空答案。

06

回归套件是自动化开发唯一的审稿人。收官夜两个 bug（宽限窗内短回复不播出、心算跳工具）都是回归测试抓到的，不是人工检视发现的。
