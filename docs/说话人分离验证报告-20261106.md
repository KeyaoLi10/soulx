# 说话人分离验证报告（2026-11-06，任务 2）

**任务来源**：用户要求（2026-11-05 深夜）——"在解决完这个任务之后去尝试一下做背景有
其他人说话下的主说话人音频分离，可以尝试 mossformer2 的这种离线方案，也可以尝试一些
sota 的流式方案，但是要记住一定要模块化，带独立开关，关闭后不要影响到其他的功能"。

**结论先行**：模块化分离基础设施已落地（sidecar :8087 + 独立开关 `speaker_sep`，默认
关、关闭零开销）；但**离线验证为负结果**——MossFormer2_SS_16K 分离 + ECAPA 挑流不能
拉开说话人验证分数带，喂给流门控也无增益，因此集成方式定为**纯影子观测**（只上报
`sep_cos`，不参与任何决策）。数据如下。

## 方案选型

- ClearVoice（pip 包 `clearvoice`）已发布的预训练模型里，**16 kHz 纯音频 TSE（以注册
  语音为条件）没有预训练版**——`AV_MossFormer2_TSE_16K` 是音视频版（需人脸/手势视频），
  纯音频 TSE 只有 8 kHz 训练代码、无 checkpoint。仓库 README 与模型注册表核实。
- 因此采用 **`MossFormer2_SS_16K`（两说话人分离，16 kHz）+ ECAPA 逐窗挑流**：正好匹配
  本场景（主说话人 + 1 个背景人声），且挑流用的 ECAPA 与 pvad 门控同源。
- SOTA 流式方案调研：当前没有可即取即用的 16 kHz 参考条件流式 TSE 预训练模型
  （NeMo 无音频 TSE 预训练；WeSep/3D-Speaker 无现成 checkpoint；DeepFilterNet 只做降噪
  不做说话人分离）。MossFormer2_SS 是当下唯一可落地的选择。

## 验证协议（复现：`scripts/tse_offline_eval.py` + `scripts/tse_score_bands.py`）

数据：a5f92f1d 取证音频（160 s，含注册前干净用户语音、背景视频段、大声数数轮、
视频下打断爆发段）。参考 = 注册窗（19:55:14–19:55:19）ECAPA 嵌入；两种参考都测过
（原始音频注册 / 分离后音频注册，即"同失真链"生产仿真）。

## 结果

### 1. 分离本身是工作的

- 注册前用户语音稳定落在 s1（与原始音频自相似 0.881）；
- 大声数数轮（19:55:57.5–60）：s1 rms 0.0396 / s2 rms **0.0020**——用户的语音被干净
  地分进一条流，另一条近乎静音。

### 2. 但 ECAPA 分数带拉不开（核心负结果）

| 段 | 原始音频 cos 带 | 挑流后 cos 带（同链参考） |
|---|---|---|
| 用户语音（真语音窗） | [−0.06, +0.79] | [+0.06, +0.70] |
| 视频独占 | [−0.04, +0.28] | [+0.01, +0.36] |
| **带间隔（用户min−视频max）** | | **−0.31（仍完全重叠）** |

重叠段（用户在视频下打断，19:56:35–46，原始 0.24–0.59）分离后 0.35–0.55——有改善
但多数仍过不了 0.5 阈值。

### 3. 喂给流门控无增益（决定性实验）

把同一套迟滞状态机分别跑在"原始分数序列"与"分离后分数序列"上：

| 段 | raw 门控压制率 | sep 门控压制率 |
|---|---|---|
| 用户语音 E1E2 | 0% | **5%（变差）** |
| 视频独占 | 100% | 100% |
| 大声数数轮 | 0% | 0% |
| 打断爆发段 | 61% | 64% |
| 视频长段 | 35% | 38% |

**根因分析**：本会话里分数带重叠的来源不是混叠污染（用户与视频极少真正同时说话，
ECAPA 在原始 1.2 s 窗上看到的本来就基本是单人），而是 ECAPA 的**说话人内方差**
（通道、韵律、窗内容）。分离解决的是它不存在的问题，还引入了自身的失真（用户段
0.51–0.55 → 0.43–0.50）。流身份也不稳定（160 s 内 17 次翻转——视频段有时进 s1 有时
进 s2），不能靠"流身份"判别。

## 落地（模块化 + 独立开关）

- **`services/tse_server.py`**（:8087，tmux `soulx:tse`，GPU 7）：无状态分离 sidecar，
  `POST /separate {audio} → {s1, s2}`。两个部署坑都已在服务端根修：ClearVoice 会直呼
  nvidia-smi 全表选卡、与 `CUDA_VISIBLE_DEVICES` 冲突（invalid device ordinal），已
  monkeypatch `SpeechModel.get_free_gpu` 尊重环境变量；模型权重 ~640 MB 按 YAML 相对
  路径 `checkpoints/MossFormer2_SS_16K` 落在**进程 cwd**（家盘 98% 满），已迁至
  `/mnt/disk3/krisl/soulx/tse_work/checkpoints`，服务启动时 `os.chdir(WORKDIR)` 固定。
  GPU 实测 1.2 s 窗 0.17 s（CPU 是 0.89× 实时，跟不上 0.4 s 门控节奏——服务必须跑 GPU）。
- **`repo/dialogue_system/speaker_sep.py`**：客户端 + `sep_shadow_round()`（分离窗口、
  双流各打一次 ECAPA 分、取高者）。一切失败静默返回 None。
- **集成点**：`PvadStreamGate._evaluate` 每轮在原始 cos 之外调一次影子观测，
  `pvad_status.sep_cos` 上报前端，转移日志带 `sep_cos=…@sN`。**不改任何决策**——
  E4 回归明确验证"sep_cos 再高、raw cos 低照样压制"。
- **开关**：`speaker_sep` 默认 **False**；关闭时模块零调用零开销。前端 Speaker Gate
  面板新增 "Speaker separation (experimental)"（`script.js?v=20261106a`）。
- **venv**：`/mnt/disk3/krisl/soulx/venv-tse`（py3.10，torch 2.4.1+cu124 匹配驱动 12.4，
  阿里 pytorch-wheels 镜像安装；MODELSCOPE_CACHE=/mnt/disk3/krisl/soulx/modelscope_cache）。

## 回归

`scripts/pvad_stream_replay.py` 新增 E 段 4 项（开关关→零调用；开→上报高分流；
sidecar 挂→None 且门控不受扰；sep 高分不改变 raw 决策），全套 **24/24**；不变量回归
selftalk 12/12、empty_stream 15/15。

## 建议（后续方向）

1. **打断段被吃的更便宜解法**：`pvad_handle_bargein` 的爆发音频本就是 2.5 s 离线形状
   窗口、且已过回声守卫+RMS 门——可考虑对 barge-in 验证单独降阈值（如 0.35），比重型
   分离划算得多（本轮实测重叠段分离后也就 0.35–0.55）。
2. 更好的 TSE 模型出现时（16 kHz、参考条件、有预训练），`speaker_sep` 的影子通道
   就是现成的 A/B 评测面：开开关对比 `sep_cos` 与 raw cos 在同一批窗口上的分布即可。
3. 若未来要用分离音频喂 ASR（而非仅打分），需先解决流身份不稳定与切窗伪影，本报告
   的数据不支持现在就上。
