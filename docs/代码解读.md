# SoulX-Duplug 对话系统 — 代码解读

> 对象：`/home/research/krisl/soulx/repo`（[Soul-AILab/SoulX-Duplug](https://github.com/Soul-AILab/SoulX-Duplug) dialogue-system 分支）
> 及本部署的自定义组件。配合总览 [../README.md](../README.md) 阅读。

## 0. 一句话原理

SoulX-Duplug 把"该不该接话"变成一个**流式的下一 token 分类问题**：
用户音频按 160ms chunk 流入，音频被 glm-4-voice tokenizer 离散化为语音 token，
经 projector 对齐到 Qwen3-0.6B（扩词表 + LoRA）的词嵌入空间，模型在每步输出
`<|user_idle|>` / `<|user_nonidle|>` / `<|user_backchannel|>` / `<|user_complete|>` /
`<|user_incomplete|>` 之一，外层状态机把这些原始状态翻译成应用层语义
（用户说完了→触发回复；用户没说完→等待；用户抢话→打断当前回复）。
**"即插即用"** 体现在：它不生成回复内容，只做轮次决策，回复由任意 LLM+TTS 级联完成。

## 2. 引擎层：turn server（:8000）

### 2.1 `server.py`（106 行）— 入口与生命周期

- FastAPI `lifespan` 里 `load_turn_model()` 加载 TurnModel（一次性、常驻显存），
  并启动 `session_gc_loop`：每 10s 扫描，60s 无音频的会话回收。
- 唯一端点 `ws /turn`：收 JSON `{type:"audio", session_id, audio: base64(float32)}`，
  按 `session_id` 懒建 `TurnSession`，`feed_audio()` 后把结果状态原路推回
  `{type:"turn_state", state, ts}`。**每个会话一份独立的 buffer/KV cache**，
  互不污染——这是 Web 端能开 10 路并发会话的基础。

### 2.2 `service/session.py` / `engine.py` — 会话与上下文快照

- `TurnSession`：包一层 `touch()` 保活 + 转发 `engine.process(audio)`。
- `TurnTakingEngine`：关键设计是 **snapshot/restore_runtime**——每个会话不持有
  模型副本，而是在处理前把 TurnModel 的全部运行时状态（audio buffer、ASR buffer、
  history chunks、wait 计数、past_state 等 dict 化快照）恢复进**共享的单个模型实例**，
  处理完再快照存回会话。多会话时分复用一张 GPU 卡上的模型。

### 2.3 `service/model.py`（735 行）— TurnModel：状态机 + 推理编排

初始化四件事：

1. **加载模型**（`_init_load_model`）：`State_Prediction_Model(config)` + Whisper
   feature extractor + 级联 ASR（paraformer，也可 sensevoice）。
2. **超参**（`_init_hyperparameters`）：chunk=2560 样本（160ms@16k）、
   back=15360（0.96s 回看）、ahead=640（40ms 前瞻）。
3. **提示嵌入**（`_init_prompt_embeds`）：预计算任务前缀
   `<|task_duplex_predict|><|punctuation_off|>` 及各状态 token 的 embedding，
   每会话的输入序列以此为起点。
4. `reset()`：随机噪声初始化环形 buffer（防止边界效应）。

核心 `state_predict()`（原始状态 → 应用状态）：

| 模型原始输出 | 条件 | 应用层动作 |
|---|---|---|
| `<|user_complete|>` | 已检测到语音 | **级联 ASR 转写整个 buffer** → 返回 `speak` + 用户话轮文本（触发下游 LLM） |
| `<|user_incomplete|>` | – | 进入 `monitoring_wait_silence`：用户似完未完，等静音确认 |
| `<|user_idle|>` | 等待确认中连续 ≥`max_wait_num`(5=0.8s) 个静音 chunk | 视为说完 → 同上返回 `speak`（兜底路径） |
| `<|user_nonidle|>` | – | 拼接 ASR buffer，返回 `nonidle`；若正在等待静音则取消等待 |
| `<|user_backchannel|>` | 未检测到正语音 | reset（"嗯/对"之类不算话轮） |
| RMS < `far_field_threshold` 且尚未检出语音 | – | 视为远场噪声，直接 reset，返回 idle |

细节：`history_chunks` 保留最近 5 个 chunk 用于把"被切断的首字"之前的静音也
拼进 ASR buffer（nonidle 分支的 `to_concat` 逻辑）；`max_mistake_num`(3) 容忍
瞬时误判。`far_field_threshold: 0` + `max_wait_num: 5` 即原 README 的基准配置。

`infer()`（每 chunk 一次前向）：`cascade_buffer` 拼接 → `_audio_to_tokens`
（back+chunk+ahead 拼段切 80ms/帧 → glm-4-voice VQ encoder）→ `_tokens_to_embeds`
（projector）→ 追加进 `past_state["input_embeds"]`（**增量 KV cache**，随历史变长）→
`_asr()` 解码增量转写（delta_text）→ `_state_predict()` 取下一 token 判状态。

### 2.4 `model/model.py`（270 行）— State_Prediction_Model：网络本体

```
音频波形 ──glm-4-voice WhisperVQEncoder(冻结)──► 语音 token
                                                    │ EncoderProjector(3 层 MLP, →1024)
                                                    ▼
              Qwen3-0.6B-expand_vocab_v2 + LoRA(r=32, α=64)
              block causal attention（块大小 12：块内全可见、块间因果）
                                                    │
              扩展词表 token: <|user_idle|> <|user_nonidle|> <|user_backchannel|>
                              <|user_complete|> <|user_incomplete|> …
```

- 训练形态是 `pl.LightningModule`（训练代码也在这份文件里），推理时只用
  `eval()` + `@torch.no_grad`。
- LoRA 权重从 `SoulX-Duplug-0.6B-Bilingual.pth` 加载；`load_state_dict` 因
  checkpoint 多一个 `embed_tokens_func.weight` 键会先 strict 失败再
  `strict=False` 重试——**日志里的报错是预期行为**。
- `model/asr.py`：`ParaformerASR`（modelscope pipeline，funasr 后端）/
  `SensevoiceASR` 二选一，只在判定"说完了"时对整段 buffer 做一次离线转写
  （级联 ASR，不在流内跑）。

### 2.5 配置 `config/config.yaml`

分 `model_config`（模型路径、LoRA 参数）与 `infer_config`（设备、种子、
`max_wait_num`/`max_mistake_num`/`far_field_threshold`、chunk 尺寸、ASR 选择）。
`config/config.py` 提供 `RunConfig` 默认值，OmegaConf merge 覆盖。

## 3. 应用层 `dialogue_system/`

### 3.1 `clients/` — 四个薄客户端

- **`vad_client.py` `TurnTaking`**：`ws://localhost:8000/turn` 的封装。
  `process(chunk)` 发 base64 音频、收 `turn_state`。结果有三种形态：
  `None`（无变化）、字符串（用户话轮文本 → 触发生成）、`[None, ...]`
  （**用户抢话 → 上层应打断当前回复**）。
- **`llm_client.py`**：三个类——`QwenLLM`（同步整段）、`QwenLLM_IndexTTS_stream`
  （默认，打我们的融合端点 `/chat_indextts`）、`QwenLLM_Cosyvoice_stream`。
  共享逻辑：每 client_id 一份会话历史（`MAX_BUFFER_SESSION=5` 轮，相邻同角色
  合并）；`generate_with_history` 逐 chunk 解析 `b"S"`文本 / `b"B"`PCM 并
  yield `{"text": 累积文本, "wav": pcm}`。
- **`tts_client.py`**：`IndexTTS_VLLM`（原版）与两个等接口 HTTP 客户端——
  **`FireRedTTS`**（剥 44 字节 WAV 头，voice=f531，打 `:8081/v1/audio/speech`）和
  **`VoxCPM_TTS`**（2026-10-27 起默认，打 `:8085/synthesize`，裸 PCM 无头）。
  三者接口统一：`synthesize(text, streaming=True)` yield int16 PCM 字节；
  公共文本清洗在模块级 `_clean_tts_text`（去 markdown 符号 + 去尾随停顿标点）；
  都在 finally 中 close response（抢话弃置流时必须关 socket）。
  `app.py` 由 `TTS_ENGINE` env 选择（默认 `voxcpm`，回滚 `firered`）。
  VoxCPM2 服务端（`services/voxcpm_tts_server.py`，:8085，GPU 7，venv-voxcpm）：
  48kHz 生成 → soxr.ResampleStream 流式重采样 24kHz → int16；producer 线程持
  GEN_LOCK 串行化 GPU（锁不横跨网络 yield），consumer 断开时置 cancel 标志，
  残余生成以单句为上界。
  **音色 = 参考克隆锚定（2026-10-29）**：zero-shot 每次调用独立采样音色
  （CFM 高斯噪声、无 seed），跨段漂移的根因；现启动时锚定一个参考 wav
  （优先级 `VOXCPM_REF_WAV` > `VOXCPM_ANCHOR_WAV`（默认
  `data/voxcpm_anchor.wav`，持久化）> 现场用模型合成校准句），
  `build_prompt_cache` 一次、每段 `_generate_with_prompt_cache` 复用；
  锚定失败自动回退 zero-shot（服务不挂）。**自训练 LoRA** 经
  `VOXCPM_LORA_PATH` 加载（显式传 checkpoint 的 r=32/alpha=32——包默认
  r=8 会静默跳过全部权重；加载校验 0 skipped 否则拒绝启动），空串禁用。
  `voice_desc` 文本描述音色已废弃（字段保留兼容但克隆模式下忽略）。
  实测：首块 80ms，RTF 0.32，段间 ECAPA 余弦 0.65-0.75（zero-shot 基线
  最低 0.22）。
- **`pvad_client.py` `PVADSession`**（2026-10-29）：主说话人门控的
  sidecar 客户端，打 `:8086`。**设计红线：绝不阻塞轮次路径**——
  `feed(wav)` 只做队列 put（wav 先 copy），daemon feeder 线程攒到
  ≥2560 样本批量 POST `/feed`，拿回的 pvad 概率存入环形数组仅作
  UI 遥测；`score(wav)` 是唯一阻塞调用（ECAPA 前向 ~120-170ms，
  POST `/score`），**只允许 worker 线程调用**（话轮门控 / 抢话门控
  线程），出错退避（0.5→5s）且 `RequestException` 一律返回 None
  （fail-open）。会话结束时 `stop()` 收 feeder 线程。

### 3.2 `app.py`（889 行）— Web 实时对话（:8090）

- **`VADModelPool`**：10 个 `TurnTaking` ws 客户端的对象池（`acquire/release`），
  每个浏览器会话独占一路，与 turn server 的 session_id 一一对应。
- **`ChatSession` / `SessionManager`**：每会话的 stop_event（打断）、pause、
  interrupt 复位等生命周期；以及 `settings`（会话级实时设置，见下）。
- **`pipeline_worker`**（线程）：核心循环——VAD 结果为文本 → 记入历史并异步
  调 LLM 流，逐段合成 TTS，把音频经 `emit_to_room` 推回浏览器（WebSocket
  `/ws`）；VAD 结果为打断信号 → set stop_event，LLM/循环立即中止（Stoppable
  的流式取消）。每轮回开始发 `turn_start`（前端清空上一行助手文本）。
- **实时设置**（2026-10-28）：`ChatSession.settings` 从 `DEFAULT_SETTINGS`
  初始化；前端 Settings 面板经 `update_config` WS 事件部分更新，
  `_merge_session_settings` 做类型校验 + 范围钳制（未知键忽略），回显
  `config_applied`。pipeline 每轮快照 settings：
  - `system_prompt`（人设/剧本）→ `llm.generate_with_history(system_prompt=…)`
  - `max_history`（记忆轮数）、`min_seg_len`（首音频分段长度）→ 同上
  - `tts_engine` → 从 `TTS_CLIENTS`（voxcpm/firered 双客户端，均已实例化）
    按会话选择
  - `tts_cfg` / `tts_timesteps` / `tts_voice_desc` → `synthesize(options=…)`
    透传给 VoxCPM 服务（FireRedTTS 忽略）
  - `pvad_mode`（off/shadow/enforce，默认 enforce）/ `pvad_threshold`
    （0.3-0.9，默认 0.5）→ 主说话人门控，见下
  注意：会话随 WS 断开销毁，重连后前端自动重发全部设置。
- **毛刺话轮过滤（2026-10-30，已下线）**：曾为治"幻听"在 websocket 音频
  循环里加 complete-turn 丢弃闸（`_BLIPTURN_FILTER`，判据为连续/近期
  nonidle chunk 计数），线上实测真人语音被误杀后整体禁用：真人麦克风语音
  经浏览器 WebRTC 处理后 turn-server 状态**逐块 nonidle/idle 交替**（永远
  无 3 连续），而幻听碎片 episode 与真人同形态，计数层面不可分。代码保留
  待新判据成立后启用；`voice_run` / `last_sustained_voice_ts` 字段与
  `scripts/blip_turn_test.py`（自动跟随开关）一并保留。分析详见
  [修改日志](修改日志.md) 2026-10-30 条及追记。
- **主说话人门控（2026-10-29）**：判定"现在说话的是不是注册主说话人"，
  **纯增强模块，不进轮次控制路径**。音频接收循环里只做三件旁路事
  （都在 `session.lock` 之外、`vad.process` 之前）：`pvad.feed(chunk)`
  （队列 put）、`mic_ring` 追加 160ms chunk（`ring_lock`，30s 环形）、
  节流 1.5s 的 `pvad_status` 遥测。真正的门控只有两个决策点，且都在
  worker 线程里：
  - **话轮门控**：`pipeline_worker` 开头 `_pvad_turn_gate`——off 直接过；
    未注册 / 语音边界环尾 <1.2s / 服务不可达 → fail-open 放行（假话轮拒绝
    是最坏失败，门控偏向放行）。**播放与空闲用同一严格阈值**：ECAPA 余弦
    < 阈值 → 发 `pvad_reject {kind:"turn"}`（shadow 模式则照常放行），被拒
    话轮不触碰播放与 LLM 历史。唯一播放期特例：**不可评分的短回声起始段**
    靠自对话文本检查拒绝（对助手近期输出做召回率 ≥0.6 的模糊匹配，TTS→ASR
    往返既错字又常只截半句）——音频对短起始段无能为力，文本是唯一判据。
    （历史注：2026-10-29 曾短暂引入"播放期宽容"——低于阈值但非自对话的
    话轮放行，理论依据是浏览器 AEC 畸变播放期的注册用户；同日经用户决定
    移除：用户实测全程戴耳机（AEC 无回声可消、不产生畸变），播放期低分
    的真实原因是参考被他人语音拉偏，而宽容恰好放行了旁人。）
  - **抢话门控（2026-10-29 打断风暴修复后）**：barge-in 信号先经迟滞——
    连续 3 个 nonidle 块（480ms）才触发判定，且每个 episode 只打断一次
    （`bargein_done`）。身份按触发它的 streak 块本身评分（≥0.9s 才可评分；
    不用 ring，避免混入上一话轮）。**播放期 fail-closed**：`playback_end`
    未到时，未注册或不可评分的抢话一律拒绝——真人会继续说、迟滞重触发后
    通过（晚 ~0.5s），而回声/噪声起始恰是不可评分的短信号。未在播放时
    维持 fail-open。
  - **说话人注册（bank + 滚动更新）**：每个过门控且 ASR 非空的话轮把 6s
    语音边界环尾存入 bank（上限 12s，短话轮跨轮累积——第 2 轮前必完成
    注册，这是线上"永久 fail-open"卡顿 bug 的直接解）；**每个过门控的话轮
    都滚动再注册**（对抗同人音色漂移：同人远段对首注册仅 0.33-0.50）。
    bank 只含过门控音频，参考不会被回声/被拒轮污染。前端 Re-enroll 按钮
    发 `pvad_enroll` 事件手动重注册。
  - **为什么门控用 ECAPA 余弦而不是 pvad 概率**：实测 pvad 概率在硬负例
    上无法区分说话人（不同说话人语音段均值 0.54 vs 主说话人 0.60；一段
    完全无关的英文播客得分 0.77 高于注册者本人的 0.58），只配当活动性
    遥测；同插件的 ECAPA 嵌入余弦则干净分离（同人 0.59-0.80，异人
    0.06-0.44），阈值 0.50。完整测量过程见
    [修改日志](修改日志.md) 2026-10-29 条。
  - **打分窗口的两个坑（实测，`scripts/ecapa_window_calib.py`）**：
    ① **拼接注册毁灭区分度**——按 160ms 语音块拼接的注册把同人 1s 窗口
    压到 0.17-0.56，与异人（0.30-0.47）完全重叠；自然连续 6s 注册下同人
    0.55-0.70 / 异人 0.30-0.47，0.5 阈值恰好落在缝隙。② **静音填充垃圾
    分**——2.5s 窗口纯语音 cos 0.57，1s 语音 + 1.5s 静音跌到 0.23，纯静音
    -0.08（话轮判定落在静音段时环尾就是这种窗口，实测同会话分数
    0.499→0.305→0.141 连续塌陷）。因此 `_pvad_ring_tail` 取环尾后只做
    **边缘静音剪除**（内部停顿保留，自然音频），再在最后一个 ≥0.6s 的
    **内部静音处按话轮切分、只留末段**（否则紧跟用户上一句的回声拿到
    混合二者的打分窗，"沾用户的光"过阈值并污染注册），语音不足 1.2s
    fail-open；抢话 streak 最低 0.9s（0.5s 窗口同人仅 0.20-0.37，
    无区分度）。
- 静态前端在 `frontend/`（深色录音室控制台风格，全宽 grid 布局：舞台 +
  400px 右栏；滚动对话日志——用户气泡随 `user_transcription` 的增长 buffer
  原地更新、助手气泡在 `turn_start` 开新条目后流式追加；无外部 CDN 依赖；
  TTS 播放 = SharedArrayBuffer 环形缓冲 24kHz + AudioWorklet `processor.js`）。
  **浏览器 WebRTC 处理链（2026-10-29）**：`getUserMedia` 约束
  `echoCancellation + noiseSuppression + autoGainControl` 全开——回声消除/
  降噪/语音增强在浏览器侧完成（与 FireRedChat 官方 demo 同款，它本身没有
  服务端 AEC 模型）。右栏 Speaker Gate 面板：模式选择、相似度阈值滑条、
  Re-enroll 按钮、enrolled 徽标 + pvad 概率实时条；`pvad_reject` 事件以
  琥珀色提示条闪现（shadow 模式注明"仅记录"）。

### 3.3 `offline_infer.py`（734 行）— 离线推理（本次交付的主路径）

`OfflineDuplexSimulator` 把"用户说话"变成**确定性的 1x 实时回放**：

1. **`_process_file`**：input.wav 重采样 16k，按 2560 样本切块；用 `_backlog_sec`
   记账实现真实时间对齐（VAD 推理耗时从睡眠预算里扣除，块间补偿）。
2. **`_handle_vad_result`** 三分支：
   - 字符串（用户话轮文本）→ `_start_generation`：先 `_flush_assistant_history`
     （把上一轮被打断的助手消息按"实际播出比例"截断后写入历史，模型视角与
     听者视角一致），再起线程 `_generation_worker`。
   - `[None,...]`（抢话）→ `_request_interruption`。
   - 其余 → 只记 states.json。
3. **`_generation_worker`**：`tts_api=None` 时走融合流——`decode_pcm_bytes`
   把 24k int16 → float32 并重采样到 16k；每段按
   `anchor_sample + latency×sr` 计算应出现的时刻入队（`_enqueue_segment`，
   段间不重叠），同时记录首包延迟。
4. **`_request_interruption`**：抢话时刻 `stop_sample` 之后的段丢弃、跨界的段
   截断；并 set stop_event 让 LLM 流停止。
5. **渲染**：`_render_assistant_wave` 把所有段按 start 叠加到与用户轨等长的
   零数组上，`_render_dialogue_wave` = 用户 + 助手混合。

**本部署补丁 `--response_tail`**：eot-bench/xyz 的输入是完整用户话轮，助手回复
大多流到输入结束之后，原版"等长裁剪"会把回复全部丢掉（首跑全静音的原因）。
补丁在渲染前把用户音轨补静音至 `assistant_end_sample + tail×sr`，完整对话得以保留。

### 3.4 `eval/` — 官方评测（本部署未跑）

`eval/evaluation/`：`eval_behavior.py`（对话行为）、`eval_pause_handling.py`
（停顿处理）、`eval_smooth_turn_taking.py`（平滑抢话）、`eval_user_interruption.py`

运行于 `venv-frc-llm`（transformers 5.x）：

  accelerate，不能用 `device_map`）；`enable_thinking=False` 的 chat template；
  GEN_LOCK 串行化 generate。
- **`/chat`**：`TextIteratorStreamer` 逐 token 流出纯文本。
- **`/chat_indextts`**：融合流。LLM 解码的同时把文本按标点
  （`，。！？：；,.!?:;` + 换行）切段，段长 ≥3 个 token 单位才值得合成；
  每段 POST FireRedTTS `stream=true` 拿 24k int16 PCM（剥 44 字节 WAV 头），
  在 executor 里跑避免阻塞事件循环。输出 chunk 约定 `b"S"+UTF-8 文本` /
  `b"B"+PCM`，与原仓库客户端逐字节兼容。
- **取消**：`StoppingCriteria` + disconnect 检测，客户端断开立即停止生成
  （避免僵尸生成占 GPU）。`_stream_tagged` 主循环有 `finally: cancel.set()`，
  正常结束/异常/GeneratorExit 一律触发停止（2026-10-26 修复，见
  [修改日志](修改日志.md)——此前断开的请求会在服务端跑满 512 token 持锁）。
- 注意点（调试时踩过的坑）：transformers 5.x 拒绝第二个 system message，
  `_build_prompt` 只在调用方未带 system 时注入 Elva 提示；`/chat` 只透出 "S" 块，
  且以 `tts=False` 跳过内部 TTS（web app 自行合成，服务端合成属纯浪费且曾在
  TTS 服务故障时把文本流拖住 180s/段）。

## 4ter. 定制层：快慢脑 Agent（`agent/` 包 + `/agent_chat` 端点，2026-10-29）

在级联底座上加"快脑即时交互 / 慢脑异步任务 / 确定性 Runtime 仲裁"双循环。
两个 LLM 实例跑同一份 `services/qwen35_fused_server.py`：**:6007 快脑
thinking=off**（即时对话 + 受理/汇报）、**:6008 慢脑 thinking=on**
（后台 agent 循环，GPU 1）。

### `/agent_chat` 线协议（qwen35_fused_server.py）

S/R/T 三通道标签流，每 chunk 一个字节前缀 + utf8：

- `S` 可说文本增量 → 快脑侧经 pop_segment 切段进 TTS；
- `R` 推理增量 → 慢脑侧直接丢弃（思考永不入语音、永不持久化）；
- `T` 完整工具调用 JSON `{"name","arguments"}`（Qwen 原生
  `<tool_call>` 标签**不是**特殊 token，模板把工具渲染进 system、
  tool 角色渲染成 user 包 `<tool_response>`；只在闭合标签后整发）。

`_TagSplitter` 是跨 chunk 的三态状态机（text/think/tool），部分标签
留在 `_partial_tail` 暂存。**最大的坑**：`enable_thinking=True` 时 chat
模板把开头的 `<think>` 预填进 prompt（流里没有开标签），splitter 必须
`start_mode="think"` 起始，否则思考内容漏进 S 通道被 TTS 读出来。

### `agent/tools.py`（慢脑工具层）

4 工具：`web_search`（DDG html 端点 POST 走 **subprocess curl**——同刻
同代理同 UA 下 requests 被 TLS 指纹挑战而 curl 通过；"anomaly" 挑战页
检测 + 一次 5s 重试，确认被挑战后进入 90s 模块级冷却，冷却内的调用
立即返回带指引的观察，防止慢脑烧穿任务预算）、`fetch_page`
（HTMLParser 正文抽取，跳 script/style/...）、`python_repl`
（`python -I` 子进程 + 20s 超时 + 一次性 cwd；**无权限隔离，研究演示
级沙箱**）、`get_datetime`。输出一律 `_clip` 截断 4000 字符，
`execute_tool` 永不抛异常。

### `agent/slow_brain.py`（后台 agent 循环客户端）

`run_task()` 阻塞式跑一个循环：任务 prompt（goal + context + 当前时间
内联，省一次 get_datetime）→ `_generate()`（解析 S/T 丢 R）→ 工具执行
→ 观察以 tool 角色回填 → 循环。MAX_STEPS=8（最后一轮撤走工具 schema
并注入"立即基于已有信息作答"），TASK_TIMEOUT_S=300 硬预算，取消检查
在流 chunk 之间（HTTP 断开由服务端 disconnect 处理器停掉生成）。
事件流 started/progress/completed/failed/canceled 驱动 Runtime 与前端。

### `agent/runtime.py`（确定性仲裁，无模型）

快脑只见 `delegate_task`/`cancel_task` 两个工具 schema；任务表
`T<n>` + 议程 + 0.5s 仲裁线程。要点：

- `delegate()` 同步执行（pipeline 线程内）：慢脑健康检查、
  MAX_RUNNING_TASKS=2 上限、起 daemon 线程、立刻返回"任务已创建"观察
  ——快脑由此马上口头受理，**不等结果**。
- 交付时机 `can_deliver()`（app 实现）= 不在生成 AND 播放结束 AND
  距用户最后语音 >1.2s；不满足就等，用户可以一直聊。
- **completed 与 failed 都入议程**（失败也要开口致歉，不能静默）；
  被打断的汇报重新入队一次（MAX_DELIVERY_ATTEMPTS=2）。
- `cancel()` 同时清洗议程（已 completed 未交付的任务也算"不再要了"）。
- `task_view()` 只列 running/queued 任务，注入快脑每次生成前的上下文。
- **`auto_cancel(user_text)` 确定性改口检测**：快脑"听懂"算了不用查了
  却不调工具（cancel_repro 实测 0/4，它把"已取消"当社交叙述直接说），
  所以由 Runtime 在生成前用正则判定改口意图（肯定式 算了/不用查/取消
  命中且存在 running 任务 → 先行取消；否定式 别取消/继续查 → 跳过），
  注入"已自动取消 T3"系统提示让快脑只做确认。prompt 规则作兜底。

### app.py / llm_client.py 集成

- `_run_speech_pipeline` 抽象 = **全系统唯一语音出口**：用户话轮与
  后台交付共用 turn_start/text_response/audio_chunk/打断截断/待提交
  语义，交付的听感与正常回复完全一致。
- `pipeline_worker` agent 路径：system_prompt + `AGENT_SYSTEM_ADDON`，
  `generate_agent_with_history(tools=FAST_TOOLS, extra_context=任务视图,
  tool_handler=runtime.handle_tool)`；`gen_in_progress` 在 try/finally
  里维护（can_deliver 的判据之一）。
- `generate_agent_with_history`（llm_client）：工具轮次全部 transient
  （assistant 原文 + tool XML 渲染、tool 观察），**永不写入
  `self.sessions`**——只有最终口语文本由 app 提交进持久历史。
  `_LEAD_ROLE_JUNK` 正则清模型偶发的行首 role 标记幻觉。
- 交付时 `_agent_deliver_entry`：把结果包成 **user 角色系统提示**
  `[系统提示：后台任务 T1（goal）已完成，以下是真实结果——...——请用
  自然口语...]` 加进历史（failed 任务的文案是致歉+说明），再用普通
  `generate_with_history` 生成汇报语音。

## 5. 端到端时序（离线推理一次"接话"）

```
t=0.00s  回放 chunk#i（160ms），vad_client → turn server
t+~30ms  State_Prediction_Model 前向 → <|user_complete|>
         状态机: cascade ASR 转写整段 buffer → "要取消下订单可以吗？"
t+~0.1s  offline_infer 收到文本 → _start_generation
         （flush 上轮被打断的历史 → 新线程）
t+0.1s   POST :6007/chat_indextts（带 5 轮历史 + Elva 提示）
t+1.1~3.6s  Qwen3.5-9B 首 token → 首个标点段 → FireRedTTS → 首个 b"B" 块
         （此即 manifest 里的 mean_llm_latency）
t+...    后续段流水线持续；期间用户音频继续回放
若用户在助手说话时出声 → turn server 判 nonidle → [None] 信号
         → stop_event + 段截断/丢弃（barge-in）
```

## 6. 已知边界与后续可做

- 官方 `eval/` 评测脚本未跑；可基于现有 24 条产物接入量化指标。
- 主说话人门控的已知弱点：① 静音间隙后头几秒内的同人抢话，streak 不足
  0.9s 时被拒（~1s 后话轮路径兜底恢复打断）；② 同人音色漂移大的远段
  （如换嗓子/离麦）可能被拒一次，滚动再注册自愈；③ 滚动再注册的固有
  边界：能过阈值的冒充者会逐步拉动参考向量（自适应说话人模型的通病，
  同人音色接近时尤甚——参考一旦被拉动，播放期/空闲期的低分可能是注册
  者本人而非旁人）；④ **流式转写不设防**：`user_transcription` 的流式
  分支来自 VAD 回调（`vad_client` 的 asr_buffer），在门控之前，旁人说话
  实时上屏、被拒后也留在对话记录里（最终文本与 turn_start 是门控后的）。
  谨慎场景可先用 shadow 模式观察，阈值可在 Settings 实时下调。
- 级联 ASR（paraformer）只覆盖中文；英文场景换 `sensevoice`（config 一行）。
- turn server 单实例多会话靠 snapshot/restore 分时复用，会话数大时
  GPU 5 是瓶颈（Web 端池上限 10）。
- `modules/` 下的 IndexTTS/CosyVoice 全量源码保留未动，若日后可下载权重，
  切回原版只需把 `app.py` 的 TTS 客户端换回 `IndexTTS_VLLM`。
