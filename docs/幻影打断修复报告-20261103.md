## 1. 摘要

安静房间里、用户全程沉默，助手 TTS 播放被反复掐停，UI 同时浮现几个幻影汉字。根因是**昨天两个改动相乘**：

1. barge-in 迟滞下线（`_BARGEIN_MIN_CHUNKS` 3→0，d808980）：首个 nonidle 块零迟赫直接触发打断；
2. pVAD 默认 off（2026-10-30 起）：说话人身份门控不在环。

两者叠加后，扬声器回声 / AEC 残留的**单个** nonidle 块（160 ms）即可瞬间掐停 TTS。排查中还发现**第二条独立打断路径**：回声毛刺让 turn server 用 1-3 字幻觉文本 commit 一个假 turn，`pipeline_worker` 里的 `session.interrupt()` 同样掐停播放。

修复为**三层防御**（仅播放期、非 enforce 模式生效）：1.6 s 滑窗内 ≥3 个 nonidle 块才允许 barge-in；播放期 nonidle < 3 的假 turn 直接丢弃；正在播的内容与识别文本相似的自说自话过滤。真人抢话（4-8 块/回合）不受影响。新增 `playback_guard` 设置与前端开关。

## 3. 根因分析

### 3.1 根因链（已确认）

```
_BARGEIN_MIN_CHUNKS = 0   (d808980, 11-02 19:55 上线)
        ×
pvad_mode = "off"         (10-30 起默认，浏览器链路同人 ECAPA 分 0.15-0.57
                           不可用，见 soulx-pvad-default-off)
        ↓
单个 nonidle 回声块 → pvad_handle_bargein → gate 不在环 → _pvad_do_bargein
        ↓
TTS 播放被瞬间掐停
```

这两个改动**单独存在都不会炸**：阈值 3 时单块毛刺被迟赫拦下（10-30 上午的日志有大量 "suppressed (1 chunk(s) < 3)" 记录，说明当时该机制在正常工作）；pvad off 但阈值 3 时同样拦下。d808980 的"已知边界"一节其实预言了这个代价（"pvad_mode=off 时毛刺同样零迟赫触发……属该取舍的预期代价"），当晚就在真实环境兑现了。

### 3.2 为什么不能改回阈值 3

旧迟赫要求 **3 个连续** nonidle 块（≈480 ms）。但浏览器 WebRTC 处理后的真人语音 nonidle/idle 约 **50% 交替**，凑不齐 3 连块——这正是 10-30 把真人抢话推迟近半秒、进而下线迟赫的原因（同一结论当时已退役了 blip-turn 过滤器）。连续计数这个判别量对真人和回声**都不成立**，恢复它只是把 bug 换回上一个 bug。

### 3.3 两条独立的打断路径

复现测试中发现掐停播放的路径有两条，必须分别堵：

| | 路径 a：回声块直接打断 | 路径 b：幻影 turn |
|---|---|---|
| 链路 | nonidle 块 → `pvad_handle_bargein` → `_pvad_do_bargein` | 回声毛刺 → turn server 以**幻觉文本** commit turn → `pipeline_worker` 中 `session.interrupt()` |
| 签名 | 早期掐停，Ratio 0.35-0.37 | 中晚期掐停；出现 1-3 字假用户消息 |
| 幻觉文本实例（实测捕获） | — | `'没事儿。'` `'急。` `'及。'` `'没。'` `'赶紧的是。'`（paraformer 对回声的典型短幻觉） | 
| 对应防御 | 层 1（滑窗门控） | 层 2（episode 计数丢弃）+ 层 3（文本过滤） |

注意路径 b 的幻觉文本是**凭空产生的**（不匹配任何正在播的内容、长度在自说自话过滤的 4 字下限以下），所以层 3 的文本匹配对它无效——这是层 2 必须存在的原因。

### 3.4 修复过程中发现并堵掉的一个回退漏洞

初版层 2 带 `sustained_recent` 回退（`last_sustained_voice_ts` 后 6 s 内放行 turn，本意是别误伤刚确认过抢话的用户）。实测 00:23 run 证伪：一次被确认的响亮回声也会刷新该时间戳，4 秒后的毛刺假 turn `'赶紧的是。'` 从这个窗口里溜了进来。**修复版本在播放期丢弃分支刻意不用该回退**（打断后场景由层 3 的 `recent_interrupt` 窗口覆盖，语义更严：要求文本确实像自己的话）。

## 4. 设计：占空比判别

核心观察是把"回声毛刺"和"真人语音"在**块级统计**上分开：

| 信号源 | 每回合 nonidle 块数 | 窗口内密度 |
|---|---|---|
| 回声/AEC 残留（线上实测、复现测试） | 1-2（episodic 毛刺，~2.2 s 一发） | 1.6 s 窗内 < 3 |
| 真人语音（浏览器 WebRTC，50% 交替） | 4-8（任何值得成句的话） | 1.6 s 窗内 ≥ 3 |

判别量取**滑窗占空比**（1.6 s 窗内 nonidle 计数 ≥ 3）而非连续计数：对 50% 交替的真人语音，10 块窗内期望 ~5 个 nonidle，必过；对 1-2 块的毛刺必拦。窗口取 1.6 s ≈ 10 块，是"真人凑满证据只损失约 1 秒（且整个抢话 episode 只损失一次）"与"毛刺永远凑不齐"之间的平衡点。

所有防御**仅播放期生效**（`now < playback_end`，含 1.5 s 收尾宽限），非播放期保持零迟赫快路径不变；pvad enforce 模式跳过（它有自己的更强 fail-close 检查）。

## 5. 改动明细

### 5.1 `app.py` — 三层防御

**会话状态**（`app.py:202-211`）：`bargein_times`（`deque`，滑窗时间戳）、`episode_nonidle`（整回合计数）、`last_nonidle_ts`（回合分隔用）。与 `bargein_streak` 的区别：跨 idle 间隙存活，专为 50% 交替的真人语音设计。

**常量与开关**（`app.py:382-407`）：

```python
_PLAYBACK_BARGEIN_WINDOW_S = 1.6   # evidence window (~10 chunks)
_PLAYBACK_BARGEIN_NONIDLE = 3      # nonidle chunks needed inside it

def _playback_guard_active(session):      # playback_guard 设置 AND 非 enforce
def _playback_bargein_deferred(session):  # 播放中 AND 证据不足
```

**层 1 — 播放期 barge-in 门控**（接收循环 nonidle 分支，`app.py:1255-1263`）：每个 nonidle 块记时间戳进滑窗，`pvad_handle_bargein` 前检查 `_playback_bargein_deferred`——证据不足时不打断也**不清 streak**（证据在积累），凑满 3 块自动放行。真人只损失约 1 秒、只损失一次。

**层 1 的事件与日志**：压制时打 `"transient barge-in suppressed (N unconfirmed chunk(s), M in 1.6s window)"` 并发 `bargein_deferred` 事件；未确认 streak 化入真 turn 时发 `bargein_deferred {"resolved":"turn"}`（前端据此不撤已确认的气泡）。

**层 2 — 幻影 turn 丢弃**（接收循环 speak 分支，`app.py:1341-1368`）：turn commit 时若仍在播放（含宽限）且 `episode_nonidle < 3`，丢弃该 turn：

```python
if (playing and _playback_guard_active(session)
        and session.episode_nonidle < _PLAYBACK_BARGEIN_NONIDLE):
    # NOTE: deliberately NO sustained-voice fallback here ...
    emit_to_room(client_id, "selftalk_drop", {"reason": "blip", ...})
    session.episode_nonidle = 0
    continue
```

日志 `"playback blip turn dropped (N nonidle chunk(s) in episode < 3): '...'"`。回合计数在 2.5 s 干净静音后重置（毛刺与毛刺之间不累计误伤）。

**层 3 — 自说自话文本过滤**（`pipeline_worker`，`app.py:804-814`）：对播放期 **或** 打断后 1.5 s 内（`recent_interrupt`——interrupt 会清零 playback_end，单看 playback_end 会漏掉刚打断的窗口）commit 的 ASR 文本跑 `_pvad_selftalk_text`（vs 正在播的 assistant 分段 / pending message / 近期历史，SequenceMatcher 召回 ≥ 0.6，4 字归一化下限）。命中则 `selftalk_drop {"reason":"selftalk"}` 并 return。

层 2 与层 3 的分工：层 3 抓**真回声转写**（文本确实像自己刚说的话），层 2 抓**短幻觉**（低于 4 字下限、与内容无关的凭空文本）。二者都不命中、而且回声确实稀疏的 turn，才可能是真人——放行。

### 5.2 `settings.py` + 前端 — `playback_guard` 开关

- `DEFAULT_SETTINGS["playback_guard"] = True`；`sanitize_updates` 尾部 bool 特判（`settings.py:140-141`）。关闭即恢复 d808980 的零迟赫裸行为（排障/对比用）。
- `frontend/index.html`：Voice Engine 面板新增 "Playback echo guard" 勾选框（含说明文案）；`frontend/script.js`：`currentSettings()`/debounced send 接线、随 frc 引擎一起置灰（SoulX 引擎专属）、`selftalk_drop` 事件处理——移除已冒出的假用户气泡 + 闪现提示"已忽略回声（识别到的是我自己的声音）"。

**实现注记**：没有复用 `pvad_reject` 事件——其前端 handler 对 `cos:null` 会执行 `cos.toFixed(2)` 直接崩（既有潜在 bug，本次绕开未修，已在日志记录）。

## 7. 已知边界

1. **播放期超短命令会被忽略**：整回合 nonidle < 3 的真人语音（如播放中只说一个"停"字）与回声毛刺在该判别量下不可区分，会被层 2 丢弃。要打断请说完整短语（"停一下"、"等一下"自然过窗）。
2. **密集干净回声仍可晚期打断**：合成干净回声若被语义 VAD 持续认成语音（≥3 in window），会通过门控——表现为 Ratio 0.91-1.00 的晚期掐停，与线上 bug 的早期签名（0.35-0.37）不同。真实浏览器 AEC 削掉回声的线性成分，线上读作 1-2 块毛刺，故此为合成侧边界。兜底：戴耳机（物理消除），或开 pvad enforce。
3. **防御事件计数天然波动**：VAD 挂钩悬崖（6.2）使线上毛刺注册率不稳定，某次会话看不到 suppressed/dropped 日志不代表防御失效——主判据是"无早掐"。
4. `pvad_reject` 前端 handler 的 `cos:null` 崩溃是既有独立 bug，本次绕开未修。

## 补遗：生成期幻影打断（当晚 01:01 第二次线上事故）

**现象**：修复上线后用户再测——第一句"喂，你好，可以听到吗？"说完、
显示正常，随后 UI 里这句话**突然被替换成"是。"**（会话 338b1765）。

### 根因：三层防御只覆盖了播放相

昨晚的修复把所有防御都键在 `playback_end` 上，但 **turn commit 到首个
TTS 音频之间还有 1-2 s 的生成窗口**（LLM 流式产出 + TTS 合成首段），
期间 `playback_end` 是陈旧的：

| 防御 | 生成窗口内的状态 |
|---|---|
| 层 1（滑窗门控） | 失效——毛刺 nonidle 块直接 `_pvad_do_bargein` → `session.interrupt()`，无条件杀死在途生成（此刻没有任何可打断的播放） |
| 层 2（episode 丢弃） | 失效——`playing = now < playback_end` 为假，幻影 turn 照常跑 pipeline，"是。" 写入 LLM 历史 |
| 层 3（自说自话） | 失效——同上，窗口判断不含生成相 |

前端侧还有一个独立的**吞句机制**：活动用户气泡在 commit 时没有冻结
（`turn_start` 要等 pipeline 开口才发），幻影 turn 的 partial/最终转写
经 `handleUserTranscription` **原地覆盖**了真实句子——用户看到的"被
吞"直接由它造成，与幻影 turn 后续是否跑完无关。

### 修复

1. **`_reply_in_flight(session)`**：`gen_in_progress OR now <
   playback_end + 1.5s`——统一"在途"窗口（生成 + 播放），三层防御
   全部改用（先例：`frc_engine.py` 早已用这一对条件）。
2. **`_begin_generation()` 在接收循环 commit 时刻调用**：原来
   `gen_in_progress` 要到 pipeline_worker 建好 LLM 生成器后才置（agent
   模式 ~0.5 s 空档），round 2 实测毛刺 barge-in 正好钻这个空档杀死了
   在途生成。配 `gen_serial` 序号：被打断的旧 pipeline 的 finally 不
   得清掉接替者的标志（顺带修掉一个既有的重叠竞态）。`_frc_commit` 与
   agent 交付路径同样接入。
3. **commit 时 `bargein_times.clear()`**：已 commit 话语的 nonidle
   证据不得为 ~0.8 s 后的毛刺背书——round 3 实测毛刺骑着 seed 语音
   未过期的窗计数凑满 3 过了门限，结构与 01:01 线上事故完全一致。
4. **惰性 burst 重置**：`episode_nonidle` 从"idle 分支 2.5 s 定时清
   零"改为"nonidle 分支里距上次 nonidle > 1.6 s 才清零"。原实现下
   2.2 s 节奏的重复毛刺会跨毛刺累计过 3 门限（round 1 发现的真漏洞）；
   改惰性后真人话轮的证据可扛任意 `turn_wait_ms`（上限 3200 ms）的
   等待静音。
