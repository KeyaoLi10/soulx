# SoulX-Duplug 系统架构总览（文字版）

> 截至 2026-10-30 · 分支 dev（`2ffdc10`）｜ 图表版见 [架构图-20261030.md](架构图-20261030.md)，可视化版见 [架构总览-20261030.html](架构总览-20261030.html)

## 0. 一句话

一个 0.6B 流式语义轮次预测模型（SoulX-Duplug）挂在 Qwen3.5-9B + VoxCPM2 级联前端上，外加**快慢脑双循环 Agent** 与**可热切换的 FireRedChat 双 EOT 前端**，构成全双工中文语音对话系统。

## 1. 分层总览

| 层 | 组件 | 职责 |
|---|---|---|
| 接入层 | 浏览器（WebRTC AEC/NS/AGC） | 回声消除与降噪；16 kHz mono，160 ms/chunk 上行 WS；播放 24 kHz PCM 分块 |
| 轮次层 | **soulx 引擎** turn server `:8000`（GPU5） | 0.6B 状态机逐 chunk 判 idle/nonidle/speak，附 paraformer 转写 |
| 轮次层 | **frc 引擎** FrcEngine（web app 内） | pvad 通用 VAD 端点检测 + ultraVAD/Qwen 双通道语义 EOT |
| 应用层 | Web app `:8090` | 会话管理、话轮门控、宽限窗、快慢脑编排、WS 事件推送 |
| 模型层 | 快脑 `:6007`（GPU6）/ 慢脑 `:6008`（GPU1） | 同一 Qwen3.5-9B 双实例：即时交互 / 后台任务 agent 循环 |
| 语音层 | VoxCPM2 `:8085`（GPU7，默认）/ FireRedTTS `:8081`（回退） | 文本分句流式合成，自训 LoRA + 锚定音色 |
| 辅助层 | pvad sidecar `:8086`（CPU） | ONNX 个性化 VAD + ECAPA 嵌入（soulx 模式下默认 off；frc 模式复用作通用 VAD） |

## 2. 音频数据流（一次对话的生命周期）

1. **上行**：麦克风 → 浏览器 WebRTC 处理链 → WS 二进制帧（16 kHz float32，160 ms）→ web app 接收循环（异采样率 soxr VHQ 重采样）。
2. **引擎分发**（按会话设置 `turn_engine`，Settings 实时切换）：
   - `soulx`：chunk 进 `session.vad.process()` → 状态机；`speak` 返回用户话轮文本 + `trigger`（`complete`=模型预测说完立即触发 / `wait`=5 块静音确认后触发）。
   - `frc`：chunk 进 `FrcEngine.feed()`，SoulX turn server 被完全旁路。
3. **话轮管线** `pipeline_worker`（每话轮一个线程）：ASR → 主说话人门控（pvad，默认 off）→ 提交上一轮 pending → interrupt/reset → 设置快照 → 历史 → 生成（agent 或普通）→ `_run_speech_pipeline` 统一语音出口。
4. **下行**：LLM 分段文本 → `text_response` 事件 + TTS 流式合成 → `audio_chunk` 二进制帧；前端按实时速率回放。

## 3. 两条轮次引擎

### 3.1 soulx（默认）

- **模型**：glm-4-voice 音频 tokenizer → projector → Qwen3-0.6B（扩词表 + LoRA），逐 chunk 流式推理；每会话独立 buffer / KV cache / 60s GC。
- **两条触发路径**：`wait`（`<|user_incomplete|>` 后连续 `max_wait_num=5` 块 ≈0.8s 静音，已确认）与 `complete`（`<|user_complete|>` 一有预测立即返回，零确认）。
- **抢话修复**：`complete` 触发的话轮在 app 侧获得 **0.9s 宽限保持窗**（`_TURN_GRACE_S`）——LLM 照常生成但全部进 `held_chunks` 对用户不可见；窗口内持续复语（≥3 块，毛刺不算）即静默丢弃整次生成（未说出的不进历史，续说经 llm_client groupby 并成完整句）；窗口平安过期则 `_flush_held()` 逐段正常播出。
- **抢话迟滞**：播放期 nonidle 需 3 连续块（480ms）才确认 barge-in，且每 episode 只打断一次。
- **毛刺话轮过滤**：`_BLIPTURN_FILTER=False`（已下线留码）。

### 3.2 frc（FireRedChat 架构，会话级热切换）

```
chunk → pvad:8086（零说话人嵌入 = 通用语音活动检测）
  onset: 3 块连续 prob≥0.5 + 2.5s 前滚防切头 → speech
  EOS:   连续 0.4s prob<0.5（概率滞后 1-2 块，实际 ≈0.6-0.7s）
  blip:  说话块 <3 → 直接丢弃；单话轮上限 60s
  → 双通道 EOT 并行（决策代际 decision_gen 校验）:
      ultraVAD:8082（20s 滚动窗 + 上一条助手文本）
      :6007 /v1/score（FireRedASR:8010 转写 + 助手文本 → 是/否首 token softmax，~60ms）
    min 融合（任一通道错误记 0），双确认 ≥0.2 → 快速提交
    否则 hold 至 EOS+6.0s 封顶提交；期间复语 → 取消待提交
  → FireRedASR 整句转写（PUNC+ITN）→ 进同一条 pipeline_worker
```

- 提交后与 soulx 模式**完全同构**（门控/历史/快慢脑/TTS 一致），且不叠加宽限窗（双 EOT 本身即防抢话）。
- 依赖 `:8086/:8082/:8010` 三服务在线；soulx 模式零依赖、零改动。

## 4. Web 应用内核（`repo/dialogue_system/app.py`）

- **接收循环**：重采样 → 引擎分发 → pvad 异步旁路 feed（不进轮次路径）→ `vad.process` → barge-in 迟滞 / 话轮线程 spawn（trigger 在循环里即时捕获，防 worker 启动晚于下一次 process 覆盖）。
- **统一语音出口** `_run_speech_pipeline`：用户话轮与后台任务交付共用——一个 `turn_start`、一个 pending-message 生命周期，打断/截断/待提交语义一致；被打断且未说出内容不提交空 assistant 消息。
- **WS 事件**（下行）：`connect_ack` / `vad_loading` / `turn_start` / `user_transcription` / `text_response` / `audio_chunk` / `circle_status` / `task_update` / `pvad_reject` / `config_applied` / `pong`；上行控制：`config_audio` / `update_config` / `duplex_stop` / `pvad_enroll` / `ping`。
- **会话设置**：`system_prompt` / `max_history` / `min_seg_len` / `tts_engine`（voxcpm|firered）/ `tts_cfg` / `tts_timesteps` / `pvad_mode`（off|shadow|enforce）/ `pvad_threshold` / `agent_enabled` / **`turn_engine`**（soulx|frc），全部实时生效、带边界钳制。

## 5. 快慢脑 Agent（`repo/dialogue_system/agent/`）

- **快脑** `:6007`（thinking=off，temperature 低）：`/agent_chat` S/R/T 三通道流（可说文本 / 推理 / 工具调用 JSON），原生 tool calling：`delegate_task`（goal 自包含）/ `cancel_task`。
- **慢脑** `:6008`（默认 thinking=off，`SLOW_BRAIN_THINKING=1` 切回）：agent 循环 4 工具——`web_search`（DDG 经 curl 直连，requests TLS 指纹被反爬；限流回落百度）、`fetch_page`、`python_repl`（子进程沙箱，20s 超时）、`get_datetime`。
- **AgentRuntime（确定性仲裁）**：
  - 任务表 / 议程；**交付时机 = 用户空闲 + 无播放 + 无生成** 的空档期，经统一语音出口，以 user 角色系统提示注入历史；
  - **`auto_cancel`**：改口正则在生成前先行取消并注入确认提示（快脑实测会口头取消却不调工具）；
  - **任务状态按提及注入**：`_TASK_MENTION_RE`（查/任务/进度/结果/好了吗/多久…）命中才注入 `task_view()`，慢脑运行期间闲聊不汇报；
  - 工具轮次不进持久历史；`task_update` 事件驱动前端 Background Tasks 面板。

## 6. 服务矩阵与部署（tmux 会话 `soulx`，10 窗口）

| 窗口 | 服务 | 端口 | GPU | venv | 说明 |
|---|---|---|---|---|---|
| `turn` | SoulX turn server | 8000 | 5 | `soulx/venv` | 0.6B 状态机 + paraformer |
| `ultravad` | ultraVAD EOT | 8082 | 5 | `eot_bench/venv` | frc 专用；唯一 transformers 4.57.1；加载 ~4min；>20s 音频 500 |
| `frcasr` | FireRedASR | 8010 | 5 | `full_duplex/venv` | frc 专用；需 tempo env ffmpeg |
| `llm` | 快脑（融合 LLM） | 6007 | 6 | `full_duplex/venv-frc-llm` | `/chat` `/agent_chat` `/v1/score` |
| `slowllm` | 慢脑 | 6008 | 1 | `full_duplex/venv-frc-llm` | 同脚本第二实例 |
| `tts` | FireRedTTS | 8081 | 7 | `full_duplex/venv` | 回退 + full_duplex 共用 |
| `voxtts` | VoxCPM2 TTS | 8085 | 7 | `soulx/venv-voxcpm` | 默认；LoRA + 锚定音色 |
| `pvad` | pvad sidecar | 8086 | – | `full_duplex/venv-frc` | CPU；唯一带 speechbrain/onnxruntime 栈 |
| `web` | Web app | 8090 | – | `soulx/venv` | FastAPI + WS |

冷启动 `bash scripts/start_services.sh`。跨 venv 服务复用是刻意设计（各 venv 钉死互不兼容的依赖栈），**不要随手升级任何共享 venv**。

## 8. 设计不变量（改代码前必读）

1. **未说出口的话绝不进历史**（截断残段 / held 未播文本都会污染下一轮生成）。
2. **跨线程/跨服务的异步结果必须带代际校验**（宽限窗、双 EOT 均为实例）。
3. **确定性逻辑放 Runtime，概率性逻辑放模型**（auto_cancel / 交付仲裁 / 提及注入都是因此从提示词下沉到代码）。
4. **pvad 旁路不进轮次路径**（feed 是队列 put；信号未知一律 fail-open）。
5. **两条引擎共享同一条 pipeline_worker 与语音出口**——前端模式只换"什么时候算说完"，不换"说完之后怎么办"。
