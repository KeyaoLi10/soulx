# PVAD 集成修复实施报告（2026-11-05 深夜）

**前置**：`docs/PVAD背景视频失效调查报告-20261105.md`（三机制定量取证：M1 barge-in
死锁、M2 分离度塌缩、M3 参考漂移）。本文记录修复的落地、回归验证与部署状态。

## 用户需求 → 架构决策

用户明确要求（原话）：*"pvad我希望是一个独立通道的门控，如果pvad识别到不是主说话人
在说话，那我希望这段音频尽量不要进到asr，不要显示到前端，之后才是更不能进入到llm中"*，
且**不能误伤不开 pvad 时的表现**。

旧架构只有事后否决（`pvad_turn_gate` 在管线入口打分、`pvad_handle_bargein` 在打断
信号上打分）——音频 100% 进 turn server，视频声先被 ASR 转写、上屏、驱动 commit，
pvad 只能事后拦"这一轮别进 LLM"。新架构把门控前移到 **ASR 之前**：

```
mic chunk ──┬─→ pvad ring（打分看原始音频，否则门永远解不开）
            ├─→ pvad sidecar /feed（取证）
            └─→ [PvadStreamGate] ── suppressing? ──→ 全零块 → turn server/ASR
                                    │                （无 nonidle、无实时字幕、
                                    │                 无 commit、无打断机制空转）
                                    └─ 否 → 原块直通
```

## 四项修复

### 1. 新模块 `repo/dialogue_system/pvad_stream.py`：pre-ASR 流门控

独立通道、每会话一个守护打分线程（0.4 s 一轮，从不阻塞收包循环）：

- **打分对象**：ring 尾部 1.2 s 语音窗（`_pvad_ring_tail`，与 turn gate 同源；<1 s
  或静音 → unscoreable → 放行）。
- **迟滞状态机**（核心设计）：调查报告 §5 实测"视频主导"与"用户被视频压住"的 ECAPA
  余弦带**完全重叠**（−0.06–0.39 vs 0.11–0.40），单一阈值必然要么漏视频要么吃用户。
  改为：
  - 连续 **2 轮 < threshold−0.20**（0.5→0.30，即"明显不是本人"持续 ~0.8 s）→ 压制；
  - 任意一轮 **≥ threshold** → 立即解除（大声说话一轮内恢复）；
  - 死区 [0.30, 0.50) → 保持现状（不打断低分连击计数）。
- **fail-open 全链路**：未注册 / 服务不可达 / unscoreable / 异常 → 一律放行。误哑
  用户是本门控最坏失败。
- **shadow 模式**只评估上报（`pvad_status.gated`）不压制。
- **作用域**：仅 SoulX 引擎（FRC 引擎有自己的 pvad endpointing）。

### 2. `pvad_gate.py`：间隙容忍的 barge-in 累积（修 M1 死锁）

`bargein_audio` 从"平铺块列表、遇 idle 块即清空"改为 **(ts, wav) 对**：

- 新 `pvad_streak_append()`：按时间淘汰（>3 s 旧证据逐出）+ 16 块上限（~2.5 s），
  **idle 间隙不再清空**——用户"停停停"被视频安静段穿插打断时证据保得住
  （实测该形态可累积 1.92 s，旧代码归零）；
- 快照 `pvad_handle_bargein` 改为拼接 `(ts, wav)` 对；
- 仅在 turn commit 时清空（会话边界语义不变）。

### 3. `pvad_gate.py`：高裕度再注册/入库（修 M3 参考漂移）

注册后，**cos ≥ threshold+0.15（0.65）** 才允许再注册或 bank 新音频——混叠窗的
0.5x 分数不再污染参考。未注册时的 bootstrap 路径不受影响。

### 4. 取证可见化（M2 的 fail-open 泄漏通道）

`pvad_turn_gate` 对"已注册 + unscoreable + fail-open 放行"新增 forensics 标记
`pass-unscoreable-short`——T14/T16 类视频短窗泄漏从此在 JSON 里可见，不再是隐形
通道。

## 不变量（"关了就当不存在"）

- `pvad_mode=off` ⇒ 收包循环根本不创建门控对象，`stream_gate_filter` 是纯直通，
  打分线程零 HTTP——延续 2026-10-30 起"pvad 默认下线零开销"的约定；
- 独立开关 `pvad_stream_gate`（默认 **on**，仅 enforce+已注册时实际生效），前端
  Speaker Gate 面板新增 "Pre-ASR audio gate" 复选框（`script.js?v=20261105b`）；
- turn server、pvad server（:8086）零改动——本次只重启了 web app。

## 回归验证

新 `scripts/pvad_stream_replay.py`（20/20 通过，跑法：
`full_duplex/venv-frc/bin/python -I scripts/pvad_stream_replay.py`，
A–C 段 stub 驱动，D 段用真实 ECAPA 回放 a5f92f1d 取证音频）：

| 段 | 内容 | 结果 |
|---|---|---|
| A | 状态机 9 项：未注册不压不评分 / 2 连低分压 / 高分解 / 死区保持并断连击 / shadow 只报不压 / 静音窗放行 / off 零评分 / 无门直通 / 压制出全零 | 9/9 |
| B | 间隙容忍 4 项：穿插爆发保 1.92 s / >3 s 淘汰 / 16 块上限 / 快照拼接 | 4/4 |
| C | 高裕度 4 项：边缘分不入库 / 高裕度入库 / bootstrap 不受影响 / 再注册要裕度 | 4/4 |
| D | 真实回放 3 项：**注册前用户语音 0% 误压**（28 轮）/ 视频独占段 95% 压制（40 轮）/ 大声数数轮全程放行（16 轮，cos 0.51–0.55 死区保持） | 3/3 |

D 段关键发现：整个会话**没有误伤任何一句真实用户语音**；视频段整体压制覆盖率 31%
不是缺陷——视频自身停顿时 unscoreable → fail-open 放行（静音无害），视频再起后
~0.8 s 内重新锁上。这是 fail-open 设计的既定代价。

不变量回归：`selftalk_replay.py` 12/12、`empty_stream_replay.py` 15/15，全过。

## 已知边界

- 用户说话中途的 ECAPA 低分凹谷（实测注册句前停顿处 cos 掉到 0.26–0.28）若持续
  ≥2 轮会短暂误压 ~0.8 s，下一轮高分即恢复——迟滞已是当前重叠带下的最优解，
  根治要靠任务 2（说话人分离拉开分数带）；
- 压制期间送 ASR 的是全零块而非断流——turn server 协议是连续的，这是刻意选择。
