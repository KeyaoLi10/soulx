# PVAD 背景视频失效调查报告（2026-11-05）

> 范围：**只查不修**。本轮不改任何代码、不重启任何服务；修复方案仅列为第 9 节建议。
> 会话：`a5f92f1d-d6bc-471c-bd6a-cba3b8b13d53`（2026-11-05 19:53–19:58，pvad **enforce** 模式），
> 日志区间 `logs/web.log` L40122–40663，turn server 侧 session `ed69c07a`（`logs/turn.log`）。

## 0. 摘要

用户先与模型正常对话，随后手机外放视频，出现三个症状。离线取证重放（`/tmp/pvad_probe/probe2.py`，
重放结果与线上记录逐项核对通过）确认了**三个机制**：

1. **打断死锁**：`app.py:1487` 在任何 idle 块上立即清空 `bargein_audio`，而背景视频的句间停顿、
   以及被 turn server RMS 门（`config.yaml:40`，`nonidle_rms_gate=0.01`）改写成 idle 的安静视频块，
   不断清零打断证据 → streak 永远凑不够 0.9s（`pvad_gate.py:64`）→ enrolled+播放中一律
   "unscoreable while playing" 拒绝（`pvad_gate.py:559-576`，fail-closed）。
2. **用户话轮全拒**：视频期间每个评分窗都是"用户+视频"混音，正常音量用户话轮对干净参考的
   ECAPA 分数跌到 **0.11–0.40**，与视频主导话轮的分数带（**-0.06–0.39**）**完全重叠**——
   单通道 ECAPA 在持续背景人声下**不存在可用阈值**，0.5 只放行"音量盖过视频"的语音
   （实测过门的大声话轮 0.52–0.69）。这就是"只有很大声才有反应"。
3. **参考漂移**：每次 verified 通过即自动 re-enroll（`pvad_gate.py:632`），而 enroll 取
   bank+tail 的**最后 5s**（`pvad_server.py:66,135`）——视频期间通过的混音频轮把视频声掺进参考，
   bank 一路涨到 12s 封顶，真用户分数随之单调衰减（T21 对 E2 还剩 0.235，对 E7 只剩 **0.098**）。

**"模型仍被视频影响"的准确解释**：纯视频话轮其实**全部被拒**（如 19:55:53「大家好，我是蒋德明律师」
cos=0.241）。实际漏进来的只有两条通道：(a) **fail-open 窗口**——非播放期的 <1.2s 短窗直接放行
（`pvad_gate.py:447-454`），19:56:43 视频原话「嗯，刚洗完，你这怎么天天晚？」就是这样过的门，
模型开始回复、用户 19:56:44 打断质问"你咋还能听到别人说话"；(b) **混音/混文本话轮 verified 过门**
（19:57:10 用户+视频混合窗 cos=0.613）。

**结论**：症状 1、3 是实现层 bug，可修；症状 2 是单通道 ECAPA 说话人验证在"持续背景同为人声"
场景下的**原理性边界**——当前组件没有任何一个做声源分离（ECAPA 只做 1:1 比对）。要在这个场景下
真正可用，需要目标说话人提取（TSE / personal VAD）或双说话人分离，见第 8、9 节。

## 4. 机制一：打断死锁（S2"打不断"）

代码链（三处叠加）：

1. **`app.py:1487`**：接收循环里任何一个 idle 块都**立即**清空 `bargein_audio`/`bargein_streak`
   （非 idle 才在 `app.py:1504-1506` 追加，16 块滚动上限）。
2. **turn server RMS 门**（`repo/service/model.py` `_apply_prelatch_gates`，`config.yaml:40`
   `nonidle_rms_gate: 0.01`）：pre-latch 阶段把 rms<0.01 的块强制改写为 idle。turn.log GATE 行显示
   视频块被分类器判 nonidle（p_nonidle 0.85–1.0）但 rms 只有 0.0004–0.008——**安静的视频块
   持续制造 idle，不断清零 streak**。
3. **`pvad_gate.py:559-576`**：enrolled + 播放中 + streak 音频 <0.9s（`_PVAD_BARGEIN_MIN_S`，
   `pvad_gate.py:64`）→ "unscoreable while playing" 拒绝（fail-closed，enforce 模式）。

日志证据：19:56:03–19:56:05 用户连喊「停停停停停停」，**1.7s 内 10 连拒**（每次 hysteresis 重过
触发一次检查、每次 streak 都 <0.9s）；同类突发还有 19:55:23、19:56:19、19:56:25、19:57:18-21、
19:57:24-25。

重放实验（§6，gap-tolerant 累积模拟——把窗口内 rms≥0.01 的"nonidle 块"拼接，即 idle 不清零的
假想实现）验证了根因和修复上限：

| 突发 | 拼接 nonidle 音频 | vs E2（干净参考） | 若实现 gap-tolerant |
|---|---|---|---|
| 19:55:23 | 1.9s | **0.832** | 过门 ✓ |
| 19:56:03-05 | 3.7s | **0.615** | 过门 ✓ |
| 19:56:19 | 1.1s | 0.354 | 仍拒 ✗（用户音量未占优） |
| 19:57:18-21（用户+视频都响） | 3.2s | **0.313** | 仍拒 ✗ |
| 19:57:24-25 | 4.5s | 0.312 | 仍拒 ✗ |

即：**streak 清零是主因**（修掉后用户音量占优的打断能过），但双方都响的混合突发仍卡在
0.31——那是机制二的分离边界。

旁证（§6b）：已 confirmed 的 11 次 barge-in 里，多数的 streak 分数其实只有 0.16–0.33，它们是靠
**"非播放期 fail-open"**（`pvad_gate.py:560` `allow = not playing or mode=="shadow"`）放行的，
并非真凭 cos≥0.5；只有 19:57:11.0（大声「没有说话呀」0.884/0.917）是凭真分数过的门。

## 5. 机制二：分离塌缩（S1"一直 listening、大声才理"）

固定用**视频开始前的干净参考 E2** 对全部话轮窗打分（重放 §4）：

| 类别 | 话轮 | vs E2 分数带 |
|---|---|---|
| 视频前用户话轮 | T1/T2/T3 | **0.57–0.86** |
| 视频期间正常音量用户话轮 | T4/T5/T7/T10/T15/T21/T22/T23 | **0.11–0.40** |
| 视频主导话轮 | T6/T8/T12/T13/T14/T16/T20 | **-0.06–0.39** |
| 视频期间**过门**的话轮（大声） | T9/T17/T18/T19 | 0.52–0.69 |
| （对照）视频主导话轮 vs 视频参考(T8窗) | T6/T7/T8 | 0.52–1.00 |

**用户带 0.11–0.40 与视频带 -0.06–0.39 完全重叠**：任何阈值都无法在"视频期间的用户话轮"和
"视频话轮"之间划线。0.5 阈值的实际语义退化为"**音量显著盖过视频的用户语音**"（0.52–0.69 过门），
这正是"只有很大声才有反应"。对照历史标定：干净音频 same 0.59–0.80 / diff 0.06–0.44（代码注释
2026-10-29）；纯浏览器链路同人 0.15–0.57（memory soulx-pvad-default-off）——背景视频把分数带
进一步压塌。

"一直 listening"来自 UI 而非门：视频音频持续被判 nonidle（GATE 行 p_nonidle≈0.99），LISTENING
状态常亮；真正的话轮提交则 51 次里 41 次被 pvad 拒掉。

## 6. 机制三：参考漂移（越用越差的放大器）

代码：每次 verified 通过即触发 `pvad_maybe_auto_enroll`（`pvad_gate.py:632`）→ enroll 音频 =
bank（12s 封顶）+ ring tail(6s)，而 `pvad_server._ecapa_tail`（`pvad_server.py:135`，
`ENROLL_WINDOW=80000`）只取**最后 5s** 的 embedding——视频期间通过的混音频轮（T9/T17/T18/T19
的窗都含视频声）把这 5s 变成混音，参考被污染。

重放漂移矩阵（用户话轮 vs 各代参考）：

| 话轮 | E1 | E2 | E3 | E4 | E5 | E6 | E7 |
|---|---|---|---|---|---|---|---|
| T7（视频主导） | 0.368 | 0.341 | **0.503** | **0.554** | 0.436 | **0.509** | 0.422 |
| T10（用户） | 0.225 | 0.324 | 0.404 | 0.409 | 0.258 | 0.248 | **0.191** |
| T21（用户） | 0.216 | 0.235 | 0.358 | 0.309 | 0.232 | 0.154 | **0.098** |

两个后果：

- **视频主导的话轮反而能过阈**：T7 对被污染的 E3/E4/E6 打到 0.50–0.55（>0.5），而对干净 E2 只有
  0.341——参考掺入视频声后，"像视频"也变成"像参考"。
- **真用户单调衰减**：T21 对 E2 还有 0.235，对 E7 只剩 0.098；T10 同步 0.32→0.19。与线上记录
  轨迹一致（0.413→0.396→0.227→**0.078**）。

这是 `pvad_gate.py` 注释里 2026-10-29 已记载的 "reference drift toward other voices" 在背景视频
场景下的完整发作：**混音轮过门 → 掺进参考 → 真用户分数更低 → 更难过门**，恶性循环。

## 7. "仍被视频影响"的准确解释（S3）

纯视频话轮全部被拒（T8 cos=0.241）。视频内容实际漏进对话的只有两条通道：

- **fail-open 短窗**（`pvad_gate.py:447-454`）：enrolled 但评分窗 <1.2s 且**不在播放中**时直接放行。
  典型案例 T16（19:56:43.4）：视频原话「嗯，刚洗完，你这怎么天天晚？」（视频里是"刚洗好你这
  直播间"）以 <1.2s 短窗放行 → 模型开始接话 → 用户 19:56:44.0 打断质问「我不是为啥你这个我都
  开了这个东西了你咋还能听到别人说话呀」。T14「好吗？」同通道。
- **混音/混文本话轮 verified 过门**：T18（19:57:10.6）窗口里用户与视频同时说话，ASR 文本
  「我直接先把这个给你…听的是我说话还」本身就是混合转写，cos=0.613 过门——**enforce 挡得住
  纯视频，挡不住"视频混进用户话轮窗"**。

（另外未注册期 T1/T2 也是 fail-open，但那时视频还没开，不构成影响。）

## 8. 现有组件能否做声音分离（答用户提问）

**不能。** 逐一核对：

- **ECAPA**（`:8086` / fireredchat_pvad 的 `_spk_extractor`）：说话人**验证**（1:1 比对），
  输入是什么就给整段的 embedding，不做分离；混音窗的 embedding 是"两把声音的平均"，正是
  本报告分离带塌缩的直接原因。
- **Paraformer / ultraVAD / turn server 分类器**：识别与活动检测，对"哪个人在说"无概念。
- **VoxCPM2 服务端降噪**：针对稳态噪声（风扇/环境），不是"同为人声的第二说话人"。

可行的分离方向（均为新增组件，非现有件改造）：

1. **目标说话人提取 / Personal VAD（推荐）**：以现有 ECAPA enrollment 向量为条件，把混音窗里的
   目标声道抽出来再验证（VoiceFilter 类方案；个人 VAD 则直接输出"目标说话人是否在说"的逐帧
   概率，可同时喂 turn server 和 pvad 门）。与现有注册流程天然衔接。
2. **盲分离后逐路验证**：modelscope ClearVoice / MossFormer2 2-speaker 分离 → 对每路跑 ECAPA →
   取目标路。不依赖注册但计算更重，且 2-speaker 假设在 >2 人场景失效。
